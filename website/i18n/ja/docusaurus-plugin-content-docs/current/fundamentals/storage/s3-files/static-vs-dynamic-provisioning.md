S3 ファイルシステムのストレージをプロビジョニングする前に、EFS CSI ドライバーが Pod にストレージをアタッチする 2 つの方法と、このラボで一方を使用する理由を理解することが重要です。

EFS CSI ドライバーは、2 つの異なるアプローチを使用して Pod にストレージをアタッチできます：

- **動的プロビジョニング**: `StorageClass` を定義し、Pod の `PersistentVolumeClaim` がストレージを要求すると、ドライバーは自動的にオンデマンドで一致する `PersistentVolume` を作成します。EFS CSI ドライバーの場合、これは `StorageClass` パラメータで参照されている既存の Amazon EFS ファイルシステムに基づいて、ドライバーが各クレームに対して新しい EFS *アクセスポイント*を作成することを意味します。
- **静的プロビジョニング**: あなた（またはあなたのインフラストラクチャ自動化）が、*事前に*ストレージバックエンドとそれを直接指す `PersistentVolume` を作成します。その後、`PersistentVolumeClaim` は、オンデマンド作成をトリガーする代わりに、その既存のボリュームにバインドします。

:::info このラボが静的プロビジョニングを使用する理由
EFS CSI ドライバーの動的プロビジョニングパスは、`StorageClass` のファイルシステム ID に対して **Amazon EFS** の `CreateAccessPoint` API を呼び出します。Amazon S3 Files ファイルシステムは別の **S3 Files** サービスに存在し、その EFS 動的プロビジョニング API を通じて作成または解決されないため、動的プロビジョニングは S3 Files ファイルシステムに対してボリュームを作成できません。

S3 Files の場合、ファイルシステムは事前に作成され（私たちの自動化がこれを行いました）、**静的にプロビジョニングされた** `PersistentVolume` を通じてマウントされます。これは、AWS が [Amazon EKS での S3 ファイルシステムのマウント](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-files-mounting-eks.html)についてドキュメント化しているプロビジョニングモデルです。
:::

:::tip S3 オブジェクトストレージの動的プロビジョニングをお探しですか？
ユースケースで Amazon S3 オブジェクトストレージをファイルシステムとして動的にオンデマンドでプロビジョニングする必要がある場合は、代わりに [Mountpoint for Amazon S3](../mountpoint-s3/index.md) モジュールを使用してください。Mountpoint for Amazon S3 は S3 バケットをファイルシステムとして公開し、独自の CSI ドライバーを通じて静的プロビジョニングと動的プロビジョニングの両方をサポートします。トレードオフは、Mountpoint が S3 Files が提供する完全な NFS ファイルシステムセマンティクス（書き込み後の読み取り一貫性やファイルロックなど）ではなく、S3 オブジェクトセマンティクス（ファイル操作を S3 API 呼び出しに変換する）を提供することです。
:::

S3 Files に静的プロビジョニングを使用する理由を理解したので、S3 ファイルシステム用の `PersistentVolume` を静的にプロビジョニングし、製品画像の保存に使用するように UI コンポーネントを変更する準備が整いました。
